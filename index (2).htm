Data

Map data as nodes and edges

Abstracting the Earth into a graph

Nodes (vertices). Intersections, dead ends, highway ramps and key locations are the discrete connection points.

G = (V, E)

Edges (links). Road segments that connect nodes, each carrying a dynamic cost weight w(e).

Edge weights. Numerical costs calculated from physical distance, speed limits, surface type and turn penalties.

Search

Three ways to search the graph

Classical

Dijkstra's algorithm

Explores outward from the origin in expanding concentric circles, like ripples in water. It evaluates every connecting node in turn, which guarantees the mathematical shortest path.

d(v) = minu∈N(v) ( d(u) + w(u,v) )

The cost is that it explores in all directions equally, including roads that lead away from the destination. A New York to Los Angeles route would examine millions of irrelevant side streets. Accurate, and far too slow for real-time global navigation.

Heuristic

A* heuristic search

Adds a directional heuristic h(n) that estimates the distance to the destination, which pulls the search straight toward the target.

f(n) = g(n) + h(n)

Here g(n) is the cost paid so far and h(n) is the optimistic estimate of what remains. Roads leading away from the target look expensive, so they wait in the queue.

Precomputed

Contraction hierarchies

Precomputes "shortcut" edges across major highway networks, so queries can skip local street networks on long journeys.

The demo above does not build real shortcuts. Its third search approximates the effect by ignoring local streets that are far from both A and B, which is why its route can cost slightly more.

Combining heuristics with a multi-level graph hierarchy reduces explored nodes from millions to a few hundred, which is what makes sub-millisecond queries possible.

Live data

Predicting traffic with machine learning

Real-time data integration

Anonymized location telemetry from mobile devices provides live velocity data across global road networks.

Graph neural networks. Deep learning models predict near-future traffic flow by analyzing temporal patterns and network dependencies.

Dynamic re-weighting. Edge weights update every few seconds to reflect actual traversal speed rather than static limits.

See a re-weight happen

Slower edges cost more, so the cheapest path moves. Trigger congestion along the current route and watch the search choose a detour.

Objectives

Multi-objective optimization

Eco-friendly routing

Calculates fuel and energy consumption using terrain elevation, incline gradients and consistent vehicle speed profiles.

User preferences & safety

Lets drivers bypass tolls, ferries, tricky left turns across multi-lane traffic or high-hazard zones. In the demo, "Avoid highways" removes the highway links from the search.

Traffic load balancing

Prevents "routing storms" by distributing traffic across multiple parallel corridors rather than sending all drivers down one narrow shortcut.

Pipeline

End-to-end navigation pipeline

  1. Graph construction

    Raw GIS road data parsed into directed graphs G = (V, E).

  2. Precomputation

    Contraction hierarchies build multi-tier highway shortcuts.

  3. Live GNN updates

    Mobile telemetry re-weights edges with dynamic travel times.

  4. Fast A* execution

    Sub-10 ms query execution returns an optimal, customized path.

Summary

The anatomy of modern routing

Representation

Discrete graph structures model physical road geometry, turn rules, speed constraints and vehicular connectivity.

Speed & scale

Precomputed contraction hierarchies and A* heuristic search reduce billions of potential roads to a focused search space.

Predictive intelligence

Machine learning transforms static distance calculations into real-time, predictive time optimization at planetary scale.
